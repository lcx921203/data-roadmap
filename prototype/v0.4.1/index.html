Apache Iceberg

开放表格式如何把对象存储上的文件变成具备 Snapshot、事务提交和演进能力的逻辑表。

L5 CoreLakehouseProduction First
30 秒理解原理生产故障项目面试

Iceberg 不是文件格式，而是 Table Format（表格式）。它通过 Metadata、Snapshot、Manifest List、Manifest 管理一组 Parquet/ORC 文件，让多个计算引擎看到一致的表状态。

它在架构中的位置

CDC / Batch / Eventssource changes
↓
Spark / Flinkcompute & write
↓
Apache Icebergtable metadata + snapshots
↓
Trino / Servingquery & consumption

核心原理

Reader 读取的是一个已提交 Snapshot，而不是根据对象存储目录里“现在有哪些文件”猜测表状态。

Table Metadata ↓ Snapshot ↓ Manifest List ↓ Manifest ↓ Data File

数仓为什么要分层？

11 direct · 5 companies查看 Evidence ›

数仓分层的核心是解耦、复用和治理。ODS 保留源系统语义，DWD 形成标准原子事实，DWS 沉淀公共主题能力，ADS 面向具体消费。生产上不机械要求五层齐全，而是保证 Raw → Conformed → Reusable Model → Serving 的职责边界清楚。

LAKEHOUSE · BACKFILL

10B rows historical backfill

假设生产规模化练习。不是项目经历。

10Brows
24hwindow
99.9%read SLO
Constraint
回填期间线上 Trino 查询不能被大规模 Shuffle 与对象存储扫描拖垮。

Where it breaks

Backfill Spark Jobs10B rows · parallel writes
↓
Iceberg Commit Layercommit contention · small files
↓
Object StorageIO / request pressure
↓
Trino Queriesplanning + scan latency

Design

按时间窗口切 Backfill，限制同时运行 Writer 数量。
控制目标文件大小，避免制造海量小文件。
在线查询与回填计算隔离资源池。
观察 Commit retries、Manifest 增长和 Query P95。

Trade-off

更高并行度缩短 Backfill 时间，但会提高 Commit 冲突、对象存储请求和线上查询干扰。目标是在 Recovery Window 与 Serving SLO 之间取平衡。
