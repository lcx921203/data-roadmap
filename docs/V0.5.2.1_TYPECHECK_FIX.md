# V0.5.2.1 Typecheck Fix

## Failure

GitHub Pages run failed at `npm run typecheck`.

TypeScript reported:

```text
Type 'KnowledgeFrontMatter' does not satisfy the constraint
'Record<string, unknown>'.
Index signature for type 'string' is missing.
```

The same issue affected `InterviewAnswerFrontMatter`.

## Root Cause

`parseFrontMatter<TMeta>` and `MarkdownDocument<TMeta>` constrained `TMeta` to:

```ts
Record<string, unknown>
```

That requires a string index signature.

Our concrete Front Matter interfaces are intentionally closed structural interfaces and do not declare arbitrary string keys, so TypeScript rejected them even though they are valid object-shaped metadata.

## Fix

Change the generic constraint to:

```ts
TMeta extends object
```

and only cast to `Record<string, unknown>` locally when dynamically reading the optional `title` key.

This preserves strong concrete Front Matter typing without weakening every metadata interface with an unnecessary index signature.

## Scope

Only two source files change:

```text
src/types/content.ts
src/content/loaders.ts
```

No content model, UI behavior, route, Evidence, or Design System rule changes.
