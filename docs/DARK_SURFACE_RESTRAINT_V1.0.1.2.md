## Observation

The V1.0.1.1 signal hue is now calmer and is kept.

The remaining visual issue is not the blue hue itself. It is the amount of blue surface area:

```text
Continue Learning
Quick Answer
```

Both currently read as large blue panels on a mostly graphite reading interface.

## Design correction

Blue returns to an accent role.

Dark mode becomes:

```text
Canvas / Reading Surface
→ graphite

Large emphasis surface
→ graphite + subtle blue tint

Signal blue
→ moving border
→ progress
→ selected state
→ label / icon
```

## Continue Learning

The card surface now mixes only a small amount of `--color-signal-soft` into `--color-surface-raised`.

The existing moving 1px border and progress bar remain the strongest blue signals.

No outer glow or shadow is added.

## Quick Answer

The block now uses a graphite raised surface with a quiet blue tint.

Blue remains in:

```text
label
subtle border
```

The article body remains the visual focus.

Code blocks remain a darker technical surface inside the block.

## Scope

Dark mode only.

Unchanged:

```text
Light Mode
layout
typography
motion
navigation
reading directory
content
```

## Principle

The product should use blue to answer:

> where should I look / what is active?

not:

> which large rectangular area owns the screen?
